# data/layers

The citywide map layers, generated by [city_layers](../../city_layers/README.md). Owner: Lise (PR 2, PR 16).
Do not edit these files by hand; rerun the pull.

```bash
python3 -m city_layers.build_layers             # pull every layer again
python3 -m city_layers.build_layers --catalog   # only rebuild catalog.json from the files here
```

## The files

- **`catalog.json`** is the answer to `GET /api/layers`: a list of `LayerCatalogEntry`, in panel order.
- **`<layer_id>.geojson`** is the answer to `GET /api/layers/{layer_id}`: a `LayerFeatureCollection`,
  which is a GeoJSON FeatureCollection with the same catalog entry under `layer`. Features are
  written one per line, so a refresh shows up in a diff as changed records.

```
{"type": "FeatureCollection",
 "layer":    {layer_id, name, description, hazard, source_name, source_url, updated_at, feature_count, status, default_on},
 "features": [{"type": "Feature", "geometry": {"type": "Point" | "MultiPolygon", "coordinates": ...},
               "properties": {id, layer_id, hazard, severity, date, title, summary, source_name, source_url, bbl, record_id}}]}
```

## Reading them

- **`status`**: `ok`; `capped` (the count is a floor, so say "at least"); `error` (the pull failed:
  `feature_count` is null and there are no features, so show "couldn't load", never zero).
- **`updated_at`** is the day the source says its rows last changed, or null when it would not say.
  The day we pulled is the last sentence of `description`.
- **`description`** also counts what is not on the map and why. Show it; it is how a layer explains itself.
- **`date`** is when the record began, as YYYY-MM-DD, or null when the source has none. For an
  as-of view keep the features dated before that day. A summary can mention something recorded
  later (a rescind date, a disposition), always with its own date.
- **`id`** is `<layer_id>:<key>` and unique in its file. **`record_id`** is the source's own record
  number, or null when the source has none (FDNY vacates, the Sandy zone).
- **`bbl`** is the lot when the record names one or its building leads to one, else null.
- **`severity`** and **`hazard`** are set per feature. A layer's own `hazard` is the one most of its
  features carry; `construction_incidents` and `structural_complaints` also hold `geotech` features.
- **`sandy_inundation`** and **`fema_flood_zones`** are polygons simplified to about 10 m, good for
  a wash on the map. Do not use them to decide about one lot; ask `city_layers.site_context`.
- **`fema_flood_zones`** and **`remediation_sites`** have no dates: they are standing context, so an
  as-of view keeps them.
- **`refresh_log.json`** is the scheduled refresh's log of its last runs, not a layer.

## Adding a layer from another module

Write `data/layers/<layer_id>.geojson` in the shape above, then run
`python3 -m city_layers.build_layers --catalog`. The catalog is rebuilt from every file in this
folder, and `tests/test_city_layers.py` checks every file here against the contracts.
